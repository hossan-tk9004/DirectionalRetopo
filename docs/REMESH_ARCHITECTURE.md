# Remesh Architecture Contract

This document records the R1 contract boundary and the decisions agreed for the
future Source Transition Scaffold redesign. It does not claim that the scaffold
algorithm is implemented yet.

## Contract boundary

`solver::RemeshInput` is an owning, Maya-independent snapshot. It contains source
positions/topology/triangulation, ordered fixed boundaries, Region membership and
transition-ring depth, portable direction and density fields, and solver settings.
No `MDagPath`, `MObject`, `MFnMesh`, `MPoint`, or `MVector` crosses this boundary.

`solver::RemeshResult` is also portable. It carries structured status/failure
codes, component topology, source mappings, exact fixed-boundary mappings,
quality metrics, timing metrics, retry information, and optional debug results.

The Maya integration layer snapshots `MeshTopologyCache`, `PaintRegionData`,
`DirectionFieldData`, and `DensityFieldData` into the contract. During R2 the
legacy implementation may still use Maya math classes internally; that is an
implementation dependency, not part of the public solver contract.

## Selected future architecture

Option B, **Source Transition Scaffold**, is the selected redesign direction:

1. the complete source boundary is fixed exactly;
2. the source Transition topology becomes the adaptation scaffold;
3. only the Core is generated by the directional remesher;
4. the scaffold progressively adapts density and flow between both interfaces.

R1-R3 preserve the current algorithm as a measurable legacy baseline. They do
not implement the scaffold, topology operations, or source-mesh replacement.

## Decisions fixed for subsequent revisions

1. Existing triangles and n-gons are valid *input scaffold* topology. Final
   generated topology is limited to triangles and quads.
2. Non-fixed Transition vertices may be locally modified by a future preview
   solver. The Maya source mesh remains read-only until an explicit commit phase.
3. For Topology Blend Width 1, the priority is interface-only refinement,
   minimal necessary triangles, then safe failure. The requested width is never
   increased automatically.
4. Splitting the Core-side interface is allowed in local preview data. Splitting,
   collapsing, or moving the fixed source boundary is forbidden.
5. Closed disk-like Regions are the first supported topology. Open Regions and
   complex holes require explicit later work.
6. The final Transition output contains triangles and quads only; unintended
   n-gons are validation failures.
7. Tiny, geometrically simple accidental holes may use local repair. Significant
   holes, disconnected components, or ambiguous topology use bounded retry and
   then a structured safe failure.

## Fixed invariants

- Fixed source boundary position, vertex count, edge count, and connectivity do
  not change.
- Source Maya geometry is never edited by preview solving.
- Direction and density fields are face-indexed snapshots and remain explicit
  solver inputs.
- Failures cross the API as stable failure codes plus diagnostics; exception text
  is not the contract.
